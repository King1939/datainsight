# DataInsight

一个基于 LLM 的数据分析 Agent：上传 CSV 或资料文件（PDF / Word / PPT / Excel / 文本 / 日志），用中文提问，Agent 自己规划、写 SQL / Python、执行、纠错，最后给出图表和结论。

不依赖 LangChain 之类的框架——Agent 循环、工具注册、错误回传全部手写，所以每一层都能讲清楚为什么这么写。

## 现在能做什么

页面上一次提问，展开的"思考过程"长这样：

```
问：哪个城市销售额最高？画个图看看对比。

[第 1 步]  1843 tokens  2.1s
[动作] run_sql
    {"sql": "SELECT city, ROUND(SUM(amount),2) AS total FROM dataset GROUP BY 1 ORDER BY 2 DESC"}
[观察] city | total
    上海 | 241589.06
    北京 | 181813.41
    ...
[第 2 步]  3120 tokens  3.4s
[动作] make_chart
    {"sql": "...", "kind": "bar", "title": "各城市销售额"}
[观察] 图表已生成：output/chart_xxx.png
```
面板下面才是答案（它不进面板——同一句话显示两遍，成本没多花，但看着像两件事）：
上海销售额最高，241,589 元，比第二名北京高 33%……

## 跑起来

```bash
python -m streamlit run app.py
```

上传任意 CSV → 中文提问 → 思考过程逐步显示（查结构 / 写 SQL / 跑代码 / 画图）→ 图表直接出现在回答上方。

也可以只传资料文件（PDF / Word / PPT / Excel / 文本 / 日志）不提 CSV：这时 Agent 用 `read_document`
分段读、`search_document` 定位，回答关于文档的问题。两类文件可以同时存在，一个问题里
既能查表、也能查文档。

`search_document` 走**混合检索**：一路 BM25 精确词匹配（错误码、专有名词、多个指标），
一路向量语义（"未履行协议怎么算赔偿"这种换个说法也要能召回），两路各自排名后用
RRF（倒数排名融合）合并——只看名次不看分数，所以不需要给 BM25 和余弦相似度做归一化，
"两路都命中"的段落天然排在"只有一路命中"前面。向量这一路没配置、超时、限流时
自动退回纯 BM25，检索本身不会失败，界面只多一句"向量检索暂时不可用"。

向量模型和对话模型**完全分开**：当前对话模型 DeepSeek 没有 `/embeddings` 端点，
复用它的配置只会 404。所以 `.env` 里另起一组（也可以存进 `data/embedding.json`）：

```bash
# 智谱 embedding-3（1024 维）
EMBEDDING_PROVIDER=openai_compat
EMBEDDING_BASE_URL=https://open.bigmodel.cn/api/paas/v4
EMBEDDING_MODEL=embedding-3
EMBEDDING_API_KEY=你的key
EMBEDDING_DIMENSIONS=1024

# 或者本机 Ollama，不用 Key
# EMBEDDING_BASE_URL=http://localhost:11434/v1
# EMBEDDING_MODEL=bge-m3
# （硅基流动：https://api.siliconflow.cn/v1 + BAAI/bge-m3；百炼：text-embedding-v3）
```

向量按**内容哈希**缓存在 `data/vault/embeddings.db`（SQLite）：同一段文字换个文件名、
换个会话都复用同一份，不重复花钱；换模型或换维度则是另一套 key，互不覆盖。
删掉这个库文件就能重建，只是下次要重新算一遍。侧边栏「启用混合检索」关掉即退回纯 BM25。

**两个上传框，按"留多久"分**：临时上传只进这次会话（关掉页面就没了，不占额度），
长期上传存进储藏区。两者都收同样的后缀——框分的是文件活多久，不是文件是什么类型；
类型仍由后缀决定，不用用户选。

**传过的文件会留在储藏区**（`data/vault/`，上限 200 MB）：原件、抽好的正文、元信息都落盘，
重启服务、换个浏览器标签页，文件还在。资料是常年可读的——不传新文件也能直接问它；
数据表要占一个 SQL 连接，所以一次只分析一张，在侧边栏点"载入"切换。

**对话也会留下**（`data/chats/`，留最近 50 个）：每轮问答自动落盘，URL 里带一个
`?c=<对话id>`，刷新、关页面、第二天回来都能接着问。存两份内容——`turns` 给人看
（问题、答案、思考过程、图表路径），`messages` 给模型看（含工具调用与返回）。
少了后者，恢复出来的对话"记得自己说过什么"但"忘了查过什么"，下一句就会自相矛盾。

**模型不写死在代码里。** 页面右上角是「⚙ 模型名」，展开后是一栏模型设置：
上面列出**已经存下的所有配置**，点一行就切过去；下面三个输入框（base_url / 模型名 /
API Key）填完点「保存并应用」，这一套就进列表，下一句话立刻用它，不用改代码也不用重启。
右栏那个「测试连接」是真连一次：发一条 `max_tokens=1` 的请求，把"哪一项填错了"
直接说出来——401 是 Key 无效、404 是地址或模型名不存在、400 多半是模型名不对。
它**只测不保存**，免得顺手把正在用的配置换掉。

配置列表存在 `data/model.json`（明文，已 gitignore），默认拿模型名当条目名；
同一个模型名挂在两个网关上时会自动带上主机名区分，不会互相覆盖。
`.env` 只是出厂默认，想退回去点「恢复默认配置」——只切换，不删列表。
Key 在界面上永远是密码框，也只显示首尾几位。

`data/sales.csv` 只作为测试固件存在，数据层不会隐式回退到它。

**能改本机文件，但需要你明确打开。** 输入框上方有一道模式开关：

| 模式 | 能做什么 | 边界 |
|---|---|---|
| 只读（默认） | 查表、读文档、跑纯计算 | 写文件一律拒绝；沙箱连 `open` / `to_csv` / `savefig` 都拦 |
| 完全工作区 | 读写本机任意路径，`list_files` / `read_file` / `write_text_file` / `edit_pptx` / `find_program` / `open_file` 全开 | 改 PPT 会自动留 `.bak` 备份；纯文本**写入不做备份**，覆盖即永久丢失；`eval` / `subprocess` 仍被禁 |

只读模式下没有上传文件就不出现提问框；切到完全工作区后，空页面也能直接说
"把桌面的 test.txt 写成三条待办"。这个开关不是装饰——`test_files.py` 里有一条
回归测试专门盯着"只读模式下 `df.to_csv()` 必须被拒"，因为早先那是个能绕过去的洞。

**说路径不用背绝对路径。** 这些写法都指向同一个文件：

```
桌面/test.txt       Desktop/test.txt      ~/Desktop/test.txt
C:/Users/你/Desktop/test.txt              C:\Users\你\Desktop\test.txt
```

桌面目录是问系统要的（`SHGetFolderPathW`），所以中文版 Windows 的「桌面」目录名、
以及被 OneDrive 重定向过的桌面都能认对。**只给 `test.txt`** 时会先看主目录、
再看桌面：找到哪份用哪份，两边都没有就报错并要求写清目录——不猜，
因为猜错的表现是"主目录凭空多一个文件，而桌面那份没变"，很难被发现。

**"打开"和"读取"是两件事。** 读取是把内容拿进上下文，`open_file` 是把控制权交给系统：
`os.startfile` 对 `.exe` / `.lnk` 就是**直接运行**，不是"查看"。所以"打开记事本里的 txt"
和"打开微信"必须走同一条路——一旦允许任意后缀，`.exe` 就在里面，按后缀维护一张
"安全清单"永远列不全（`.docm` 带宏、`.url` 会联网、`.hta` 本身就是脚本）。
于是它和写入归在同一档：只在「完全工作区」可用。

说"打开微信"不用给路径：`find_program` 翻开始菜单里的 `.lnk`（只翻快捷方式，
不扫 `Program Files` 那几万个 `.exe`），拿到路径再交给 `open_file`。这台机器上
`find_program("微信")` 返回的就是 `ProgramData\…\Start Menu\Programs\微信\微信.lnk`。
工具回复只会说"已请求系统打开"——窗口是系统弹的，模型看不见它到底开没开。

## 十二个设计取舍

**1. 工具的结构由签名派生，描述由人写。**
参数名、类型、必填项、枚举值全部从函数签名推导，不再手抄一份 JSON；但"这个工具什么时候该用"必须人写，机器推不出来。

**注册表靠导入副作用，所以新工具文件不会自己出现。** 写一个 `*_tools.py` 只是躺在目录里，要等 `app.tools` 被导入时才执行装饰器。界面进程已经在跑时，`import app.tools` 直接命中 `sys.modules` 缓存，那行 import 不会重跑——文件在、模型却看不到，只能重启进程。现在每次 rerun 都会调一次 `load_missing()`（`pkgutil` 扫目录 + 只导没加载过的），新文件立刻进注册表。改**已有**模块的代码仍需重启，因为重复执行会撞上注册表的重名检查。
消掉的是**两份结构互相漂移**的风险，不是"写文档"这件事本身。

**2. 错误是数据，不是异常。**
工具里的任何异常都被转成字符串回到模型手里。模型看到 `no such column: revenue` 才会自己改；如果程序直接崩了，它就永远学不会。

**3. 预算优先于正确。**
步数上限（40 步）、token 上限（80k）、重复调用检测——三个刹车。Agent 出错时最常见的表现不是报错，而是**安静地烧钱**。
其中步数只是**兜底**，不是日常额度：正常任务（读几份资料、查几次表、改个文件）十来步很常见，
把上限压到 8 这类小值，结果是活干到一半被掐断，而用户分不清"它做不完"还是"不让它做"。
真撞上了也不作废——上下文都还在，说一句「继续」就能接着做。

**4. 护栏不是安全边界。**
`run_python` 跑在独立子进程里，先过 AST 白名单再过超时与输出截断。它能挡住模型手滑和明显越权，
**挡不住蓄意攻击**（`pandas.read_csv` 照样能读任意文件）。所以文档里写的是「受限执行环境」，
不是「安全沙箱」。把边界说清楚，比假装安全更值钱。
沙箱的 import 白名单里**没有 matplotlib**，两种模式都没有：子进程画的图回不到界面，
放行只会让模型以为画好了。真拦到时报错会直接指路 `make_chart`，
否则模型会换个库接着试，一步步烧掉预算。

**5. 外部输入在边界处适配，不让内部跟着变。**
上传的 CSV 不管叫什么名字，都注册成同一个视图名 `dataset`（`config.TABLE_NAME`）。这样一个界面需求
没有波及注册表、工具描述、模型看到的表名。反过来做（表名跟着文件名走）看着灵活，实际上会让
四五个地方同时跟着变，而且模型每换一个文件就得重新学表名。
名字取中性的 `dataset` 而不是 `sales`：后者是第 1 周示例订单表的遗留，用户传一份医院数据时，
prompt 里写着"电商订单表 sales"就是在给模型错误暗示。

**6. 文档正文不进上下文，只给索引和分页。**
资料文件的正文一个字都不放进 system prompt，只给"文件名 / 字数 / 段数"。要看内容，
模型得调 `read_document(name, part=2)`；要找东西，用 `search_document` 定位到第几段。
理由和 `run_sql` 的 `max_rows` 一样：**能力上限靠工具，成本上限靠接口设计**。
一次把 40 页 PDF 塞进上下文，看着"方便"，实际上是让模型在一堆无关段落里找答案，
又贵又更容易看错。

`search_document` 自己也是照这条原则设计的：它**默认搜全部资料**（不必先猜是哪一份），
多关键词按 OR 处理，但返回的只是三段"候选卡片"——文件名 + 段号 + 命中处一百来字，
不给整段。一段是 2000 字，八处命中就能撑满 4000 字符的观察上限；给卡片则一次约 450 token，
模型看完再决定读哪一段。整词一个都没命中时才降级到按字（bigram）模糊匹配，
并且要求覆盖率 60% 以上、结果必须标明"这是字面相近"——没有这道闸，
`不存在的词甲乙丙` 会靠"存在"两个字撞出几十段假候选。

**7. 上传入口按格式自动分派，不按下游能力分叉。**
第一版做了两个上传框："CSV"一个、"资料"一个。这是把内部实现（表 vs 文本）暴露成了
用户的选择题——传错框不会有任何提示，用户只会觉得「这程序不认我的文件」。
中间只有过一个框，后缀决定走哪条路：CSV 变成可查询的表，其余抽成可检索的文字。
**变成表是对 CSV 的增强，不是另一种文件类型**，这个判断程序做得比用户准。

后来又分回两个框，但分的维度换了：**按留多久分，不按是什么分**。临时上传只进本次会话，
长期上传落进储藏区。用户脑子里真有这个问题（"这份东西我要不要留着？"），
而"它是表还是文档"没有——后者继续由后缀决定，谁也不用回答。

**8. 出图不该要求先有一份表。**
`make_chart` 原来只收一条 SQL，而 SQL 只能跑在唯一那个 `dataset` 视图上——于是"画张图"隐含了
"必须先上传 CSV"。可文档里读到的数字、`run_python` 算出来的结果，本来都不是表，却只能绕回去变成表。
现在它收两样：有表时传 `sql`，没有表时直接传 `labels` + `values` 两列数字。
画图的代码只有一份，分叉只在"数据从哪来"这一步。

思维导图则单独一个 `make_mindmap`，没有塞进 `make_chart`。理由不是"多一个工具更专一"这种话，
而是输入形状根本不同：一个吃两列数，一个吃树。合并就得让 `sql / labels / values / paths`
四种参数互相排斥，模型每画一次图先要做一道选择题，出错率比多记一个工具名高得多。
树的输入用「路径列表」（`[["中心","分支","叶"]]`）而不是嵌套 JSON：JSON Schema 里就是 array 套 array，
而且模型写嵌套 dict 时少一个括号整段作废，路径列表错一条只废一条。

**9. 幻灯片只给版式，不给坐标。**
`make_pptx` 的每页只有一个 `layout`（封面/章节/要点/指标/表格/对比/结束），
没有 `x`、`y`、`font_size` 这类字段。放开坐标，模型前 9 页排得还行，第 10 页就开始
把字压在边框上——而一份 20 页的稿子，人不会逐页检查。固定版式把"会不会重叠"
变成不可能发生，而不是靠事后发现。可变的部分放在参数里：`theme`（两套配色）、
`size`（16:9 / 4:3）、`margin`（三档留白）。

真正的难点不是画，是**写之前的估字**。python-pptx 给不了渲染结果，所以每个文本块
先按可用宽高算行数，放不下就降字号（18→11），到 11 还放不下才截断并在返回里点名第几页。
这里踩过两个坑：中文一个字占 1em 不是 0.5em（按 0.5 算会把每行容量算成两倍，判断"放得下"然后溢出到页脚），
以及 PowerPoint 的单倍行高约等于 1.2 倍字号（漏掉这个系数，整页高度差 20%）。

估完字还要处理"放得下但显得空"：三条要点配 18pt，只占半页，全挤在顶部会像没写完。
所以富余高度会摊进段间距（上限 26pt，再多就松成双倍行距了）；对比页两栏的字号统一取
较小值，否则会出现左栏 16pt、右栏 13pt，一页两种正文大小。

**10. 改一份 PPT 走增量编辑，不重新生成整份。**

这条是踩出来的。用户说"往这份 PPT 里加一页"，当时的工具只有 `make_pptx`，
于是模型把 12 页全部重排成 16 页——他没让我改的那 12 页也全成了新对象，
文件从 48KB 变成 55KB，改动范围说不清。重建对"从零做一份"是对的，
对"改一份已有的"是错的。

于是有了 `edit_pptx(path, ops)`：四种操作（插页 / 改字 / 删页 / 挪位置），
定位用**页码 + 块号**。块是**段落级**而不是形状级——一页要点是一个文本框里的 5 个段落，
只到形状的话，改第 2 条要点就得把 5 条全重写一遍。
页码必须重排：插一页之后，后面每页的页脚都错了，所以改完要整份刷一遍。

两条硬要求：**要么全成、要么文件不动**（任何一步失败就整体回退，不写盘），
以及**写之前留 `.bak` 备份**（文本文件不做备份是有意的，但一份 20 页的稿子被改坏不可逆）。

顺带一条教训：那次事故里模型连着六次无效调用才读出一份 PPT 的内容——
它先 `import pptx` 被拒，再试 `zipfile`、`zlib`、`__import__`，最后靠 `sys.modules`
才凑出一个能用的模块。白名单第一次报错就写全了，缺的是**指路**：
现在沙箱拦下 `zipfile` / `pptx` / `openpyxl` 时会直接说"读文件用 `read_file`，
改 PPT 用 `edit_pptx`"，并把 `read_file` 扩成能读 PDF / Word / PPT / Excel 的统一入口。
工具能读的格式越少，模型越会绕道去用通用工具硬扛，而那条路注定更难走。

**11. 临时上传归会话，不归磁盘。**

界面上写着"关掉页面就没了"，磁盘上这件事却一直没做：每次上传按 `<sid>.csv` 和
`<sid>/` 落一份副本，而 sid 只活在 `session_state` 里，对话文件也不记它——进程一重启，
这些副本没有任何代码路径读得到。没人删的结果是 367 个 34 字节的 csv 加一份 8.6 MB 的课件。

现在三个时刻各收一次：**进程启动**扫掉上一次的遗留、**切/新建/删除对话**删当前那份、
**撤下临时表**只删 csv（同一会话的资料还得能读）。判遗留看 `mtime` 而不是"整个清空"，
因为本进程刚写进去的可能正被另一个标签页用着——这条界线同时挡住了测试误伤，
界面测试会把 `app.py` 跑一遍，也就是把清理跑一遍，所以它们必须隔离上传区。

代价写在明处：两个实例挂同一个 `data` 目录时，后启动的仍会清掉先启动的旧文件。
这和 `index.json` 被抢写是同一个问题，前提是"一个 data 目录只跑一个实例"。

**12. 「思考过程」只记调了什么，不铺返回正文。**

读一份 12 页的 PPT，返回是两千字大纲，原样贴在面板里能把整页顶穿。现在除首行摘要
（`<路径>（12 页 · 16:9 · 商务蓝）`）和「注意 / 警告」那几行，正文一律折成
「共 1,699 字，正文已省略」。

门槛分两档而不是一刀切，因为这两类返回的性质不同：`read_file` / `read_document`
返回的**就是文件本身**，四页的 PPT 也是正文，按 160 字就折叠；`edit_pptx` / `make_pptx`
返回的是**状态**（改了哪几页、备份在哪、有没有压到页脚），三五百字很正常，得到 600 字
才折。报错另算——`错误：` 开头的一律原样显示，工具坏了却因为"太长"被折叠，界面上就
什么都看不见了。

这里要分清一件容易混的事：**面板上的字从来没进过模型上下文**。它只是 `on_event`
回调渲染给人看的，删掉它省不下一分 token。真正的 token 是 `role: tool` 那条消息，
属于输入侧，而且模型必须看到内容才能干活——想省只能靠 `read_file(part=N)` 分段读，
或者调小 `MAX_OBS_CHARS`，两者都在拿质量换钱。这次改的是可读性和聊天文件的体积
（`turns[].trace` 会落盘），不是账单。

**13. 「当前用哪份数据」不能是进程级全局。**

duckdb 连接早就按会话 id 分开存了，但"现在是哪一份"仍然写成 `_active = "default"`。
后果不是报错，是**串数据**：A 标签页问一句要跑十几秒，这期间 B 刷新页面就把 `_active`
改成 B 的会话 id，A 后面几步的 `run_sql` 全部查到 B 的表；`run_python` 更糟，它按当前
key 找 CSV，会拿别人的文件算完一份"像模像样"的结果。用两个线程复现过：A 绑北京的 999，
200ms 后查出来的是 B 的表。

改成 `contextvars.ContextVar` 后每个标签页在自己线程里 set，互不可见。注入点有两处：
`_init_state()`（每次 rerun 的第一件事）和 `Agent.ask()` 入口。

**只写，不还原。** 最初这里还有一个 `reset_key()`，用 `try/finally` 把 key 还回
调用前的值。后来发现它是多余的：一次 rerun 就是一根新线程，下次刷新必然重设，
"留在上下文里的值"活不过一次刷新。实测把还原改成空函数，449 条测试里只有两条
专门测还原的会红，功能一条没坏。删掉之后少了一层 token 传递，读代码的人不用先
理解 Token 是什么。

为什么不给工具加个 `sid` 参数：工具签名会被 `build_tool_spec` 直接变成 JSON Schema 交给
模型，多一个参数模型就会自己编一个值塞进来。上下文注入是唯一不改进工具签名、也不出现在
schema 里的办法。

验证方式分两层：`tests/test_isolation.py` 用真线程跑并发（还做了变异测试——把
`current_key` 换回全局变量，用例立刻红）；界面层用 `AppTest` 拦 `use_dataset` 的调用，
确认它发生在 `ScriptRunner.scriptThread` 上、且参数就是本次会话的 sid，而测试主线程的
`current_key()` 始终是 `default`——这恰好证明了两个执行上下文互不影响。

还没做的：`files._mode`（只读/完全工作区）和模型选择仍是进程级。模型选择本来就该是
全局偏好，没问题；但写权限开关是**安全边界**——B 标签页在只读下提问时，A 把开关拨到
"完全工作区"，B 那边也会拿到写权限。要不要也按标签页隔离，待定。

## 评测

两个纯开发期脚本，不接进运行时、不改 `app/` 一行代码，也不引 ragas / trulens 这类外部框架。
语料和 `data/sales.csv` 都是固定的（`data/make_data.py` 固定种子），所以同一份配置重复跑，指标应当稳定。

### 检索召回：MRR@K / Hit@K / Recall@K

```bash
python eval/eval_retrieval.py                    # bm25 / vector / hybrid 三路对比
python eval/eval_retrieval.py --compare-rewrite  # 前置查询改写前后对比
```

24 条标注按「文档名 + 段号」对齐，覆盖精确词、多词共现、自然语言语义、跨语言四类。

### 生成质量：忠实度 + 答案相关性

```bash
python eval/eval_generation.py --matrix                       # 4 种配置 × 全部用例
python eval/eval_generation.py --ids g01,g07 --rewrite        # 只跑指定用例
python eval/eval_generation.py --predictions eval/predictions_gen.json   # 读快照复评，不重跑 Agent
```

- **忠实度**：把答案拆成原子事实声明，逐条对照本轮 `tool` 观察判
  `supported / unsupported / contradicted`，得分 = 支持数 ÷ 声明总数；出现矛盾直接判 fail。
  答案里的每条声明都能追到具体工具与原文片段，Bad Case 会打印出来。
- **相关性**：让 Judge 只看答案反推 3 个它最可能回答的问题，再和实际提问算向量余弦取均值。
  直接让模型打 0~1 分偏宽，逆向问题更稳；没配向量或接口异常时平滑退回 Judge 评分。
- **拒答正交处理**：资料里确实没有的问题，诚实说"没找到"拿满忠实度、相关性记 0，
  和"编一个答案"彻底分开；`expect_refusal` 与判定不符会单独计数。
- `--matrix` 一次跑四组配置：`baseline`（关闭改写）、`basic_rewrite`（开改写）、
  `colloquial`（口语化问法）、`cross_lingual`（英文问法），用同一批用例看前置改写救回了多少。
- `--save-predictions` 落盘后，换 Judge 模型、调阈值都不用再花生成的钱。
